# Changelog

## [Unreleased]

- **`scripts/dev-with-builder.sh --real` starts a Builder Studio can use** (#730). It started Builder with neither `KPUBDATA_BUILDER_ALLOWED_ORIGINS` nor `--warehouse`: Builder's CORS is default-deny and Vite has no proxy, so every call from `localhost:5173` was refused, and without a warehouse the Tables and SQL screens got 404. It now allows `http://localhost:5173` and `http://127.0.0.1:5173` and passes `--warehouse build/warehouse` (a value already exported for either wins), and stops with an error when Builder is not ready in 30 seconds instead of starting Studio anyway. Without `--real` it no longer starts a Builder that demo mode never calls. The READMEs' manual steps carry the same two settings.
- **The Profile tab reads a trimmed column range** (#732, builder#903, Builder API contract 1.77.0). Builder now reports a numeric or temporal column's min and max after leaving out its 5 lowest and 5 highest values, so that one record's extreme is not disclosed, with `status: trimmed` instead of `exact`. `columnRangeSchema` rejected that status, which would have turned the whole tab into an error; it now accepts `trimmed`, `trimmed_count` and the profile's `range_trim`. A trimmed range says "위·아래 각 5개 값을 뺀 범위" under it, and the note above the table says the range is what remains after the extremes are left out instead of calling every figure exact. An earlier Builder's `exact` range is shown as before.
- **The Ask KPubData cancel test no longer hangs under load** (#735). `__tests__/assistantSession.test.tsx`'s abortable stream added its abort listener only when the stream was read, so a cancel that arrived first — the order on a busy runner — left a promise that never settled: the test timed out at 60 seconds and the 16 after it failed on a null hook result. The helper now rejects at once on an already-aborted signal, as a real provider's fetch does, and a test pins that order. No application code changed.
- **A build of an uploaded file no longer fails at 30 seconds, and a preview is sent once** (#723, #724). The synchronous `POST /build` — the only route that builds a file source — used the default 30-second client timeout, so a longer build ended as a 408 while Builder was still running it, and a second click started the same build again; it now has no client timeout, like publish, and is still cancelled by the caller. `POST /preview` used the default two retries on a 5xx, a timeout or a dropped connection, so one click could call the provider three times with the user's key and spend three times the quota; it is now sent once and a failure is shown. `/validate`, which carries no key, is retried as before.
- **Assistant and provenance marks use Brand v2 tokens instead of raw indigo and violet** (#676, refs #628). `src/globals.css` gains `--assistant-accent`, `--assistant-accent-text`, `--assistant-accent-subtle` and `--assistant-accent-border` (light, dark and OS-dark), in Data Cyan's hue: the only new value is the light text colour `#0E7490`, the darker cyan that reaches 4.5:1 (White 5.36, its own tint 4.89); the tint and border sit below the gate's chroma threshold. The Report provenance badge, Assistant blocks and preview, the pending-notes card on Reports and the mock markers in Ask KPubData — ten places — now read these tokens, so that area no longer looks like Brand v1 Indigo. `__tests__/brandV2Gate.test.ts` fails if a raw `indigo-*`, `violet-*` or `purple-*` Tailwind class returns to `src/`, if a token is missing or equals an interaction or status colour, or if Assistant text drops below 4.5:1. `docs/brand/VISUAL_IDENTITY.md` §3.7 records the tokens and their use. KPubData Watch mirrors every Studio token, so its `brand-v2.css` needs the same four.
- **The test setup runs on msw 3** (#718). `msw` goes from 2.15.0 to 3.0.0 and `typescript-eslint` from 8.70.1 to 8.71.0. msw 3 renamed the `listen()` option `onUnhandledRequest` to `onUnhandledFrame`; `vitest.setup.ts` and the two Builder API suites pass the same values as before (`warn`, and `error` in `builderApiE2E`), so an unhandled request is treated exactly as strictly. msw 3 intercepts at the socket, so a mocked response arrives a turn later than it did: four tests that acted before the response was handled now wait for it — the sync `/build` cases in `asyncBuildJob.test.ts` advance the fake clock like the async ones, `specRevisionPanel.test.tsx` and `ProviderPage.multiUser.test.tsx` wait for the button they click, and `adminScreen.test.tsx` waits for the policy, which comes from a different request than the runs. `package.json` gains an `overrides` entry pointing `vitest` and `@vitest/mocker`'s optional `msw` peer (`^2.4.9`) at the installed msw: without it Node 22's npm 10 refuses `npm ci` ("Missing: msw@2.15.0 from lock file"). Remove it once vitest's peer range admits msw 3. No application code changed.

- **A saved analysis Builder will not run again as it is says so instead of failing** (#565, kpubdata-builder#875, contract 1.75.0 or later). `savedAnalysisSchema` reads Builder's optional `sql_dialect`, `engine`, `engine_version`, `query_contract_version` and `migration_required`; a Builder without them reads as before. An analysis with `migration_required` — saved before Builder's SQL changed — has **Run again** disabled and a notice: Builder SQL changed after it was saved, so open it in SQL Workspace, check the SQL and save it as a new analysis. Opening it there loads its SQL and name as before and says the same; saving it as a new analysis clears the notice. If a run is refused anyway with 409 `analysis_migration_required` (a list read from an older Builder), the card shows the same notice, not an error. Studio does not show the dialect or engine names: to a user it is Builder SQL. The contract drift check passes against Builder main and against the contract with these fields.
- **The publish page previews the data card before publishing** (#646, kpubdata-builder#906 and #955, contract 1.75.0). Each Gold output's `card.json` — found as `gold/<source key>/card.json` in `GET /artifacts/{run_id}` and read with `GET /artifacts/{run_id}/{file_path}`, whose body the contract declares as `DatasetCard` (mirrored as `datasetCardSchema`) — is rendered section by section in Korean and English: per source the attribution, source URL, licence and collection time, then the processing steps and the personal-information summary, in Builder's own words. A licence that differs from the one the KPubData catalogue declares is flagged as a warning with the provider's licence beside it, from `license_mismatch`, `license_declared` and `license_provider`; `processing_declared: false` reads "No processing", apart from an empty section, which is marked as blocking publishing; a composed output's last step (two provenance entries) is labelled as its join. A card written before 1.75.0 lacks those fields, and only then are the facts read from Builder's sentences (`…; the provider declares: …`, `No transformation declared: …`, `Joined … (… join)`). A run without a card says so; a card Builder withholds by policy says why; a failed read shows only its HTTP status, never the response body. The contract drift check now resolves a response `oneOf` with a single `$ref` member, so the artifact route's `DatasetCard` examples in `fixtures/responses.json` are parsed with Studio's schema.
- **The Administration page shows "N of M" runs when Builder sends a total** (#702, kpubdata-builder#948/#956, contract 1.73.0). `adminRunsResponseSchema` reads the optional `total` — the runs before `limit` — next to `count`, the runs in this response. With it the All runs card reads "Showing N of M runs" (실행 N / M건) and offers **Show more** only while `count < total`, so a full page that is every run no longer suggests there may be more; after the contract's maximum `limit` of 200 it says how many older runs are not shown. A Builder without `total` keeps the #661 behaviour: "all N" for a short page, "latest N, there may be more" with **Show more** for a full one.

Every example's `error` must also come out as the shown message. Examples Studio shows only as their message are listed in `ERROR_READERS` with the reason; an unlisted example, a listed one the contract dropped, or a not-handled example that gains a code fails the check. A fixtures file declaring contract 1.72.0 or later must carry a non-empty `error_fixtures`; older ones may leave it out. Tests rewrite the examples the way a breaking change would — `current_revision` renamed, a sign-up code renamed, a new example — and show each fails. `httpError` (`builderApi.ts`) and `asInvalidDetails` (`features/validation/api`) are exported for it.

- **Studio sends a Content-Security-Policy** (#663, refs #619). Scripts and styles run only from Studio's own origin — no inline script, no `<style>` element, no eval — and `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`. Every `vite build` (the GitHub Pages demo, the release tarball, `vite preview`) carries it as a `<meta http-equiv>` in `index.html` from one definition, `src/shared/config/contentSecurityPolicy.ts`. The container image builds without the meta and nginx sends it as a header with `frame-ancestors 'self'`: `docker/40-kpubdata-config.sh` writes it at start with that deployment's `BUILDER_API_URL` and `OIDC_ISSUER` origins added to `connect-src` (the issuer also to `frame-src`, for the silent SSO iframe), and refuses a URL whose origin is not a plain http(s) host. `silent-check-sso.html` gets its own header allowing just its inline script by hash. `connect-src` allows any HTTPS origin plus `http://localhost:*`/`http://127.0.0.1:*`, because the Builder URL and issuer are runtime settings and Ask KPubData's BYOK base URL can be any HTTPS address; `frame-src` likewise. The dev server sends no policy (React Fast Refresh injects an inline script). To run under it, the report editor's print rules moved from an inline `<style>` to `globals.css` (`body:has(#report-print-area)`), and `zod` resolves to `src/shared/lib/zodJitless.ts`, which sets `jitless` before any schema is built so zod's `new Function` probe no longer reports a violation. A new Playwright project, `csp-chromium`, builds the app and serves it with `vite preview`; `e2e/csp.spec.ts` walks the core screens, the assistant demo and report creation with no violation, checks that Builder/OIDC/BYOK HTTPS and local-HTTP endpoints are reachable, and that an injected inline script, a `<style>` element and a plain-HTTP foreign host are blocked. `__tests__/contentSecurityPolicy.test.ts` keeps the shell's header equal to the meta policy, checks the hash against the file and fails if a component renders a `<style>` element.

- **Spec edits are kept as a server-side revision history** (#649, kpubdata-builder#820, contract 1.59.0). The spec edit screen (`/refresh-jobs/:buildId/edit`) gains a **Change history** panel over `PUT`/`GET /revisions/spec/{doc_id}`, `GET .../history` and `POST .../revert`, keyed by the opened spec's table id. ### Security

- **`Secret scan (gitleaks)` no longer fails on another branch's commits** (#685). Without `--log-opts`, gitleaks runs `git log --all`, which — combined with `fetch-depth: 0` pulling in every remote branch — walked unmerged PR branches too, so a synthetic test key on someone else's open branch turned main's scan, and every other PR's scan, red. The job now scopes `--log-opts` to the run's own commits: a pull request scans `base..head`, a push to `main` scans `before..sha` (or just `sha` for a brand-new branch, where `before` is all zeros), and `schedule`/`workflow_dispatch` scan the default branch's full history only — never another branch. `.gitleaksignore` is unaffected.
- The repository no longer tracks `.next/` and `next-env.d.ts` — 229 files of Next.js build output committed by accident with #402, in a project built with Vite (kpubdata-builder#691). A new `Security` workflow runs `npm audit` over `package-lock.json`, gitleaks over the full history and CodeQL, on every pull request and weekly; the history's reviewed findings (that build's per-build Next keys, and synthetic keys in redaction tests) are listed with their reasons in `.gitleaksignore`.
